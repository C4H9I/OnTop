# Правила разработки OnTop

## Назначение приложения

OnTop — Android-приложение, которое помогает пользователю регулярно возвращать внимание к важным мыслям, идеям, принципам, целям и наблюдениям.

Основная сущность — визуальная карточка с короткой фразой, подробным текстом и необязательным изображением. Карточки отображаются на плиточной доске. Пользователь может дополнять их комментариями, которые формируют историю размышлений.

## Первая версия

1. Создание и редактирование карточек.
2. Плиточная доска с несколькими размерами карточек.
3. Просмотр карточки и добавление комментариев.
4. Виджет Android для выбранной карточки.
5. Гибкие повторяющиеся напоминания.
6. Экспорт и восстановление данных.

## Технологии

* Kotlin и Jetpack Compose.
* Room для локального хранения.
* Jetpack Glance для виджетов.
* AlarmManager для напоминаний, требующих точного времени, с учётом ограничений Android.
* WorkManager для фоновых задач без требования точного времени.

Это целевой набор технологий; фактическое состояние реализации и зависимостей фиксируется в PROJECT\_STATUS.md.

## Принципы разработки

* Первая версия полностью локальная, без сервера и регистрации.
* Интерфейс ориентирован на смартфон.
* Добавление мысли должно быть быстрым.
* Основной текст карточки должен легко читаться.
* Карточки не являются задачами, которые обязательно нужно завершать.
* Не добавлять облако, ИИ-функции, социальные функции и монетизацию без отдельного решения.
* Не усложнять архитектуру без необходимости.
* Использовать существующие соглашения проекта.
* Работать небольшими завершёнными этапами.
* Не менять версии зависимостей без обоснования.
* После изменений выполнять доступные проверки.
* Не утверждать, что сборка или тесты прошли, если они не запускались.
* Перед значительными изменениями изучать PROJECT\_STATUS.md.
* После завершённого этапа обновлять PROJECT\_STATUS.md.
* Не создавать Git-коммиты и не выполнять push без отдельного указания пользователя.
* Перед удалением файлов или другими потенциально разрушительными действиями запрашивать подтверждение.




## UI/UX Quality Standards

When working on any user interface:

1. Always use relevant installed UI/UX skills.
2. Before implementation, define the visual direction,
design system, typography, colors and spacing.
3. Follow native platform conventions:

   * Desktop: Windows, macOS and Linux guidelines.
   * Mobile: iOS and Android guidelines.
4. Never blindly reuse desktop layouts on mobile.
5. Ensure responsive layouts, accessibility and
consistent component behavior.
6. Implement loading, empty, error and success states.
7. Review the finished UI and fix visual inconsistencies.
8. Avoid generic AI-generated interface patterns.
9. Prefer reusable components and design tokens.
10. Do not sacrifice usability for visual aesthetics.




## Отчёты об изменениях

В каждом отчёте указывать:

1. Что реализовано.
2. Какие файлы изменены.
3. Какие проверки выполнены и их результаты.
4. Какие ограничения остаются.
